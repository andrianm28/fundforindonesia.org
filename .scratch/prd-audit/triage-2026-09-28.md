## Bagian B — Tiket 06: temuan workflow mana yang diperbaiki, dan bagaimana

❓ **Q1 - [HIGH] Review independen tidak diposting sebagai GitHub review
untuk 10 PR uang terakhir**: `get_reviews` kosong untuk semua PR uang yang
disampel; satu-satunya jejak review adalah prosa di badan PR/commit penulis
sendiri (mis. PR #100). **Nuansa koordinator**: untuk PR #121, review
independen Standards + Spec dan re-review-nya *memang dijalankan* sebagai
subagent yang di-dispatch koordinator — bukan dilewati. Celahnya bukan
"review dilewati", melainkan hasilnya tidak pernah diposting ke PR, jadi
tidak ada jejak audit yang bisa dibaca ulang siapa pun di luar percakapan
sesi koordinator itu sendiri. Opsi: fix-now / new-rule / accept.
➡️ Rekomendasi: **new-rule** — wajibkan hasil reviewer independen diposkan
sebagai `pull_request_review_write` atau `add_issue_comment` yang
sesungguhnya, bukan hanya dirangkum ke pesan commit penulis. Ini memberi
tiket 05/06 berikutnya sesuatu yang bisa diaudit ulang, bukan menata ulang
narasi dari memori sesi.

❓ **Q2 - [HIGH] Tiket `prd-compliance-fase-0-2/issues/35` mengklaim
`done (PR #93, 9e3e6d6)` padahal PR #93 `closed, merged: false`**: Fiturnya
(`COLLECTION_ACCOUNT`, `ProviderWithdrawal`) memang ada di `main`, tapi
mendarat lewat PR #108 (`pr93-carried`) di commit `a1889fe`, bukan PR
#93/`9e3e6d6`. Opsi: fix-now / new-rule / accept.
➡️ Rekomendasi: **fix-now** — ubah baris Status tiket 35 menjadi
`done (PR #108, a1889fe)`. Ini koreksi satu baris, tidak perlu aturan baru;
mekanismenya ("carry trap") sudah didokumentasikan di
`rilis-1-benda/handoff-2026-09-28.md`.

❓ **Q3 - [MEDIUM] `AGENTS.md` dan `handoff-map.md` sempat berbeda soal
batas agent background (4 vs 8)**: `AGENTS.md` (`ef4a8a2`) sudah mengganti
batas datar 4 dengan penjelasan "yang diukur adalah 4 vCPU, bukan jumlah
agent", tapi `handoff-map.md:176` (ditulis 2026-09-27, belum disentuh sejak)
masih bilang "paling banyak 4 background subagent". Opsi: fix-now /
new-rule / accept.
➡️ Rekomendasi: **new-rule** — jangan lagi mengulang angka batas di dokumen
handoff sama sekali; cukup rujuk ke `AGENTS.md` sebagai satu-satunya sumber
aturan tiering/dispatch (`AGENTS.md` sendiri sudah mengklaim peran itu untuk
proyek ini). Mencegah drift yang sama terulang di handoff berikutnya.

❓ **Q4 - [MEDIUM] `CONTEXT.md` bukan glosarium murni — tiga entri membawa
path file dan identifier kode**: Baris Usage Report, Dormant Balance, dan

➡️ Rekomendasi: **new-rule** — pertahankan catatan "belum ada kodenya" (itu
fakta domain yang sah), tapi hapus path/identifier spesifiknya; cukup "belum
ada kode yang menulis ini" tanpa menyebut file, supaya klaimnya tidak basi
begitu ada refactor tak terkait.

❓ **Q5 - [LOW] Sejumlah commit uang mendarat di `main` tanpa bentuk "Merge

➡️ Rekomendasi: **accept, tracked** — ini gejala dari "carry trap" yang

❓ **Q6 - [INFO] Salinan vendored `.claude/skills/` belum dihapus**: Sesuai
